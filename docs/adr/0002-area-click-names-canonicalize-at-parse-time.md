# Area-click names canonicalize at parse time

Reorderings of the documented area-click names (edge regions, corners, and the bare `edge-click`/`corner-click` forms) are accepted and rewritten to the canonical name in one place, the parse-time slug lookup in `src/Config.m`, so dispatch, the menu, app-scope override matching, and skipped-line reporting see only canonical names. Bag-of-words matching is ambiguous for the edge-region family (`left-edge-top-half-click` and `top-edge-left-half-click` share a word multiset), so the direction word attached to `edge` names the edge and the remaining direction and size words form the part; an ordering still ambiguous after that rule is rejected. Two constraints follow: a future gesture name must not share a word multiset with an existing name unless an adjacency rule can split them, and any name-level feature must operate on canonical space through this parse-time chokepoint.
