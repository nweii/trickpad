# Fn and Globe output events on macOS

## Conclusion

A normal macOS app with event-synthesis permission can send Fn-modified keyboard actions through CoreGraphics. The blanket claim that Fn cannot be part of an output action is too strong.

CoreGraphics exposes `kCGEventFlagMaskSecondaryFn`, defines it as the state in which Fn is down, permits an app to set event flags, and permits the app to post the event into the system event stream. An Fn chord can therefore use ordinary key-down and key-up events carrying that flag. Apple also exposes post-event access as a permission checked by `CGPreflightPostEventAccess`. [CGEventFlags](https://developer.apple.com/documentation/coregraphics/cgeventflags), [CGEventSetFlags](https://developer.apple.com/documentation/coregraphics/cgeventsetflags), [CGEventPost](https://developer.apple.com/documentation/coregraphics/cgevent/post%28tap%3A%29), [CGPreflightPostEventAccess](https://developer.apple.com/documentation/coregraphics/cgpreflightposteventaccess%28%29)

CoreGraphics can also represent Fn itself as modifier transitions. `CGEventCreateKeyboardEvent` generates the appropriate key-down, key-up, or flags-changed event from a virtual key code. Apple’s HID source maps both Apple Fn HID usages to virtual key code `0x3f`, classifies that code as `NX_MODIFIERKEY_SECONDARYFN`, and emits `NX_FLAGSCHANGED` events for modifier changes. A `0x3f` down/up pair is therefore the supported Quartz representation of Fn down/up, rather than an ordinary character key. [CGEventCreateKeyboardEvent](https://developer.apple.com/documentation/coregraphics/cgevent/init%28keyboardeventsource%3Avirtualkey%3Akeydown%3A%29), [Fn HID translation](https://github.com/apple-oss-distributions/IOHIDFamily/blob/777ccd9698845aadf711e32d843c8c9b777431d9/IOHIDFamily/IOHIDKeyboard.cpp#L245-L264), [modifier event generation](https://github.com/apple-oss-distributions/IOHIDFamily/blob/777ccd9698845aadf711e32d843c8c9b777431d9/IOHIDSystem/IOHIKeyboardMapper.cpp#L738-L808)

## Event-layer distinctions

| Layer | Fn or Globe representation | Relevance to output |
|---|---|---|
| CoreGraphics | `kCGEventFlagMaskSecondaryFn`; virtual key `0x3f` produces Fn flags-changed transitions | This is the public system-wide synthesis route for Fn chords and Fn down/up. |
| AppKit `NSEvent` | `.function`, the same device-independent bit | This describes received or constructed AppKit events. `NSApplication.postEvent` adds an event only to that app’s queue, so it is not the system-shortcut injection route. The `.function` flag also describes F and navigation keys, making its name broader than the CoreGraphics Fn flag. [NSEvent function flag](https://developer.apple.com/documentation/appkit/nsevent/modifierflags-swift.struct/function), [NSApplication event queue](https://developer.apple.com/documentation/appkit/nsapplication/postevent%28_%3Aatstart%3A%29) |
| `NX_SYSDEFINED` | Auxiliary special-key events such as volume, brightness, and media controls | Fn is absent from `NX_KEYTYPE_*` and is instead `NX_MODIFIERKEY_SECONDARYFN`. A fabricated `NX_SYSDEFINED` media-style event is not the Fn route. [Apple special-key and modifier definitions](https://github.com/apple-oss-distributions/IOHIDFamily/blob/777ccd9698845aadf711e32d843c8c9b777431d9/IOHIDSystem/IOKit/hidsystem/ev_keymap.h#L48-L113), [`NX_SYSDEFINED` event type](https://github.com/apple-oss-distributions/IOHIDFamily/blob/777ccd9698845aadf711e32d843c8c9b777431d9/IOHIDSystem/IOKit/hidsystem/IOLLEvent.h#L105-L113), [Fn mask](https://github.com/apple-oss-distributions/IOHIDFamily/blob/777ccd9698845aadf711e32d843c8c9b777431d9/IOHIDSystem/IOKit/hidsystem/IOLLEvent.h#L240-L248) |
| HID | Apple vendor Fn usage; Consumer page `0x0c`, usage `0x029d` for next keyboard-layout selection | The USB tables contain no standard Keyboard-page Fn modifier; Apple handles Fn through vendor usages. Apple separately marks Consumer usage `0x029d` as Globe support. Posting that exact HID signal requires a virtual HID device, whose public Apple interface requires `com.apple.developer.hid.virtual.device`. [USB HID Usage Tables 1.7, pp. 89–95 and 135](https://www.usb.org/sites/default/files/hut1_7.pdf), [Apple Globe detection](https://github.com/apple-oss-distributions/IOHIDFamily/blob/777ccd9698845aadf711e32d843c8c9b777431d9/IOHIDFamily/IOHIDEventDriver.cpp#L2397-L2412), [virtual HID entitlement](https://github.com/apple-oss-distributions/IOHIDFamily/blob/777ccd9698845aadf711e32d843c8c9b777431d9/HID/Headers/HIDUserDevice.h#L38-L55) |

## Product boundary

Fn-modified output actions are technically available through Trickpad’s existing CoreGraphics event layer. A robust sequence should post Fn down, the other key down and up with the Fn flag, then Fn up, matching the modifier sequence Apple documents for other modifiers.

The primary sources do not guarantee that a synthetic Fn-only `0x3f` down/up pair invokes every configurable standalone Fn or Globe action, such as Character Viewer or input-source switching. Those actions may distinguish Quartz Fn transitions from the separate Globe HID usage. Treat standalone Fn/Globe as unverified until a development bundle proves the intended macOS shortcut on supported macOS versions. An unentitled normal app has no documented route to emit the exact Globe HID usage.
